Reading: four times the budget raises acceptance by 7-10 points but leaves the edge gap between
accepted and rejected graphs unchanged (n=18: ~4.9 / ~3.7 edges; n=15: ~3.1), at 2-7x the time.
The density selection comes from the graphs, not from too few layout proposals.
Decision (DECISIONS 2026-11-12): keep budget 180; size-OOD for the main build is [13, 16].
Because the gap already exists at n=15, the cap alone does not remove it: every split reports
edges per root, and size-OOD is also scored on a slice matched to ID edges-per-node.
s/graph depends on machine load (the 18-node budget-180 rows took 0.45-0.51 s/graph on an idle
core in `docs/layout_capacity.md`), so compare timings only within a row pair.
